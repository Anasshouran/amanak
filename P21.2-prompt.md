| Block/unblock | security_admin, super_admin (existing) |

**Backend enforces. UI hides buttons for non-super_admin.**

Add helper in `backend/common/staff.py`:
```python
def is_super_admin(user) -> bool:
    if not user.is_authenticated:
        return False
    if user.is_superuser:
        return True
    return user.groups.filter(name="super_admin").exists()
```

## 3. Backend endpoints

All require `IsAuthenticated` + `is_super_admin`.

### 3.1 POST `/api/v1/staff/users/` — create user

Body:
```json
{
  "email": "user@example.com",
  "username": "username",
  "password": "StrongPass123!",
  "first_name": "Ahmed",
  "last_name": "Ali",
  "is_active": true,
  "is_staff": false,
  "is_superuser": false,
  "groups": ["support"]
}
```

Validation:
- `email`: unique, valid format
- `username`: unique, 3-30 chars, alphanumeric + underscore
- `password`: min 12 chars, must meet existing validators (reuse `validate_password`)
- `groups`: list of existing group names
- `is_superuser=true` requires caller `is_superuser=true` (even super_admin group cannot create superusers unless themselves superuser)

Response (201): user object (same as `UserSerializer`)

Errors (400): field-level errors, same shape as Django's `UserCreationForm`

### 3.2 PATCH `/api/v1/staff/users/{id}/` — update user

Editable fields:
- `first_name`, `last_name`
- `is_active` (deactivate, not delete)
- `groups` (change role)
- **NOT** `email` or `username` (immutable — prevents identity confusion)
- **NOT** `password` (separate reset flow)

Validation:
- Cannot deactivate self
- Cannot remove last `superuser` group from a superuser
- Cannot change `is_superuser` via PATCH (only via Django Admin)

Response (200): user object

### 3.3 POST `/api/v1/staff/users/{id}/reset-password/` — trigger password reset

Body:
```json
{
  "new_password": "StrongerPass456!",
  "confirm_password": "StrongerPass456!"
}
```

- Validates `new_password` meets requirements
- Sets password directly (no email required — admin action)
- **Invalidates all user's refresh tokens** (security)
- Cannot reset own password via this endpoint (must use regular flow)

Response (200): `{"detail": "Password updated"}`

### 3.4 DELETE `/api/v1/staff/users/{id}/` — soft delete

- Requires confirmation body: `{"confirm_email": "user@example.com"}` (must match target)
- **Soft delete**: sets `is_active=False`, does NOT remove DB row
- Cascade: logout all sessions (blacklist tokens)
- Cannot delete self
- Cannot delete another superuser (even super_admin cannot)
- Audit log entry required

Response (200): `{"detail": "User deactivated"}`

**NEVER hard-delete users via API.** Hard deletion only via Django Admin or management command.
